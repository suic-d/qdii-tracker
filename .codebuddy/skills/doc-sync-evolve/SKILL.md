# doc-sync-evolve — 经验沉淀向导

当用户要求将经验/教训/规则沉淀到文档系统时，按以下决策树决定目标文件，然后 **仅输出变更提议**，不直接写入。

## 分流决策（不写入文件正文，仅给用户看）

1. **这是每次任务都要遵守的行为约束？**
   → 建议写入 AGENT.md（Critical Rules 或对应章节）
   → 但如果只是代码级细节（如"某函数第3个参数是bool"）→ 不写，CodeGraph 可查

2. **这是跨会话必须记住的变更事实？**
   → 建议写入 MEMORY.md（最近变更 + 关键约定）

3. **这是偶发踩坑、bug记录、代码级细节？**
   → 建议写入 knowledge/gotchas.md（含复现步骤 + 版本范围）

4. **这是架构级决策（为什么选A不选B）？**
   → 建议写入 knowledge/adr/（编号递增）

5. **规则与现有约束冲突？**
   → **必须指出冲突**并让人裁决，不能悄悄覆盖

## 输出格式

```
**建议文件**：AGENT.md / MEMORY.md / knowledge/gotchas.md / knowledge/adr/
**写入位置**：{章节名}
**变更内容**：
{完整的 markdown 文本，可直接插入}
**冲突警告**：{如有，描述与现有规则的冲突；如无，写 NONE}
**理由**：{为什么需要这条规则，不遵守会怎样}
```

## Gotchas

- 不是所有错误都该进 AGENT.md。先问：边界条件？测试。架构缺陷？重构。Review 漏洞？改流程。
- 如果提议的新规则与现有规则矛盾，必须指出冲突并让人裁决
- 如果 MEMORY.md 超过 50 行，建议合并/归档而非追加
